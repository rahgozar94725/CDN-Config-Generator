## What changed

`generateConfigs` now strips a trailing dot from `host` itself, in both builders,
so V15's host clause is a property of the function rather than of the app that
calls it. Feed `info.example.com.` straight past the V14 gate and the generated
link carries `host=info.example.com`; `sni` still carries the trailing dot random
SNI gives it. No §V row, no gate rule and no other module changed.

### Verification

*The V15 assertion the plan wrote for R5 passes at `multiplier.test.js:256` against
unmutated code, and goes red when either strip is removed.* — confirmed, with one
correction to the plan's line number and one thing the plan did not anticipate. The
assertion `expect(out[0]).not.toMatch(/host=[^&#]*\.(?=[&#]|$)/)` now lives at
`multiplier.test.js:270` — the plan wrote `:256` before R5's own edits shifted the
file — inside the `V7, V15:` test, and it passes against unmutated code. It goes red
under mutation A. It does **not** go red under mutation B, because it is a
query-string regex and a vmess link is base64. That is why the inherited work added a
second, decoded assertion for the vmess builder rather than relying on this one:
read literally, the plan's "either strip" is only covered by the pair of assertions,
not by this one alone. Keeping it as written and adding the vmess test satisfies the
plan's intent — each strip has a red — without weakening the original assertion.

### The `btoa` vs `encodeBase64` question

Kept `btoa`. The file's actual idiom is `btoa` — five of its six vmess payloads use
it (`:189`, `:203`, `:240`, `:275`, `:326`). The single `encodeBase64` at `:213` is
the `AE1:` test, whose payload is `'سرور تهران 🚀'`; `btoa` throws on non-Latin1, so
that line is a necessity, not a preference. The new test's payload is pure ASCII and
sits four lines from `:240`, which is `btoa`. Switching it would have made it the odd
one out, and pulling the parser's own encoder into a test whose subject is the
generator adds a dependency the assertion does not need.

- **9. The public surface is honest** — the one item that applies. The observable

  yields a `host` without one, in both link shapes. Reaching it requires bypassing
  the V14 gate in `rows.js`, so no UI path produces it today, but `generateConfigs`
