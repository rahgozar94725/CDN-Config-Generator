## What changed

Deleting or renaming one of the three `src/meta/` gate files now turns the suite
red and names the file that went missing, instead of the suite passing with the
gate silently gone. `vite.config.js` also states its test `include` explicitly,
so the set of collected test files is a written decision rather than a default.

## Files

- `src/meta/traceability.test.js` — new `describe`: `readdirSync(src/meta)` must
  contain all three gate filenames, failing with the missing names listed.
- `vite.config.js` — added `test: { include: ['src/**/*.test.js'] }` alongside
  the existing `base` and `plugins` keys.

### What this does not catch

Descoping is not catchable by any test in this suite, and this unit does not
change that. If vitest stops collecting `src/meta/` — a narrowed `include`, an
`exclude`, a moved directory — then no assertion inside those files runs, so
nothing is left to report their absence. A suite cannot detect that it was not
asked to run. The explicit `test.include` in `vite.config.js` is a guard against
the natural next edit, not a detector: it makes the collected set a visible line
in a reviewed file, nothing more.

Deleting all three gate files at once is also not caught, for the same reason —
the assertion lives inside one of the files it audits. It catches one or two
going missing, which is the realistic accident.

## Production pass

1. `readdirSync(join(root, 'src', 'meta'))` throws `ENOENT` if the directory is
   gone, rather than failing the assertion with a message. Accepted: this test
   file lives in that directory, so if the directory is gone the file is not
   collected and there is no assertion to reach. The throw is unreachable in
   practice, and a crashed run is red either way.
2-8. n/a — a synchronous read of one repo directory in a test process. No
   untrusted input, no secrets, no handles held open, nothing remote, ~3 entries
   scanned once, no production code path, and both changes revert by `git
   revert`.
9. `vite.config.js` is a public surface and this changes a default: vitest's
   built-in `include` (which also picks up `.spec.` files, `.ts`/`.jsx`, and any
   test outside `src/`) is now replaced by `src/**/*.test.js`. Every test file
   added in future must match that glob or it will not run. Stated in the commit
   message; the collected count was checked before and after to prove nothing
   existing was dropped.

## Notes for the next unit

R3 edits `src/meta/locales.test.js` — a different file, no conflict.

What is worth carrying: all three gates read the filesystem directly with
`node:fs` against `root` computed from `import.meta.url`, with no shared helper
between the files. `traceability.test.js` now has two independent
`readdirSync` calls (`docs/adr/`, `src/meta/`) plus a recursive `walk` of `src/`.
If R3 adds a third filesystem read in `locales.test.js`, note that the presence
check added here is the only one that treats a *missing* file as a failure —
every other read treats whatever it finds as the truth, so an empty or shrunken
input still passes unless a canary assertion says otherwise. `traceability.js`
handles that with its `found the tables it audits` test; the presence check
needs no such canary because an empty directory listing already fails it with
all three names.
