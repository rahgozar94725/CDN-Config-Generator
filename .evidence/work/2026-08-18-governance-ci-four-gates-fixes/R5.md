## Deviation from the plan, and why

The plan directed the new assertion `not.toMatch(/host=[^&#]*\.(?=[&#]|$)/)` onto
`multiplier.test.js:256`. Added there it is **red against unmutated production code**:

```
AssertionError: expected 'vless://uuid@9.9.9.9:443?type=ws&host…' not to match /host=[^&#]*\.(?=[&#]|$)/
+ Received:
"vless://uuid@9.9.9.9:443?type=ws&host=info.example.com.&security=tls&sni=307e9lhihrr.example.com.&insecure=0&allowInsecure=0&alpn=h2&fp=chrome#cfg-001"
      Tests  1 failed | 30 passed (31)
```

That test deliberately feeds `host=info.example.com.`, bypassing the V14 gate, to prove
root extraction survives it. There is no host-side guard to survive it with:
`multiplier.js:82` is `p.host = config.routingSubdomain` and `:119` is the same for
vmess. The only trailing-dot guard in the generator is `extractRootDomain`
(`multiplier.js:151`), and it guards `sni`.

The plan's own words for this unit are "the code is correct and the tests were weak".
For V15's host clause that premise does not hold, so the assertion was placed on the
test at :137, where the routing subdomain is legitimate (`info.example.com`), random
SNI is on, and V15's actual claim — the dot belongs to `sni` alone — is exactly what is
being generated. That test now carries the `V15` tag. `:256` keeps its `V7, V15` tag,
which is correct for V15's third clause ("root-domain extraction ignores one if present").

No production file was changed. See the decision below.

### The V15 host clause has no production guard

- **Question:** should `buildQueryLink`/`buildVmess` strip a trailing dot from `host`,
  making V15 literally true of `generateConfigs`, or is V15's host clause meant to be
  satisfied upstream by the V14 gate?
- **Option A — one line each at `multiplier.js:82` and `:119`
  (`.replace(/\.+$/, '')`).** This is the same argument the code already makes for
  `sni` at `multiplier.js:146`: "a pure function should not depend on a UI gate for
  correctness". After it, the plan's assertion at `:256` passes as written.
- **Option B — amend V15's §V row** to say the host clause is enforced by V14 before
  generation, and leave the generator alone.
- **Recommendation:** A. It is one line per builder, it makes `∀ generated link` in
  V15 true of the function rather than of the app, and it removes the asymmetry where
  `sni` is defended against a bypassed gate and `host` is not. But it is a production
  change with a §V bearing and it is outside this unit's `Files`, so it is not taken here.
- **Decided:** the repository owner chose **A** on 2026-08-20 and granted the authority.
  Implemented in **R12** — `.replace(/\.+$/, '')` on `host` in `buildQueryLink` and in
  `buildVmess`, each proved by its own mutation. `SPEC.md` §V row V15 is unchanged.
  R12's record: `.evidence/work/2026-08-18-governance-ci-four-gates-fixes/R12.md`.
