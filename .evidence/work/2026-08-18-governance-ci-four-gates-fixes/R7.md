# R7 — Run the build on every pull request

status: done

## What changed

Every pull request now compiles the app: the `test` job runs `npm run build`
after the suite, so a change that breaks the Vite build turns CI red instead of
merging green and failing later in the Pages deploy on master. The job's `npm ci`
also runs with `--ignore-scripts`, so a lockfile proposed by a non-maintainer can
no longer execute install hooks on the runner.

## Files

- `.github/workflows/ci.yml` — `npm ci` → `npm ci --ignore-scripts`; added
  `- run: npm run build` as the final step of the `test` job.

### `--ignore-scripts` does not break anything

Verified twice rather than assumed:

- Dependency tree: `grep -c hasInstallScript package-lock.json` → 2, and both are
  benign — `esbuild@0.21.5` (its postinstall only validates a binary that ships
  inside the `@esbuild/*` platform package the resolver loads at runtime) and
  `fsevents@2.3.3` (`optional`, `os: [darwin]`, never installed on the runner).
- Empirically, locally: `npm ci --ignore-scripts` → `npm run test` (997 passed)
  → `npm run build` (`✓ built in 4.46s`, 45 modules).
- Empirically, on the ubuntu runner: steps 4 and 5 of run 32257236772 both
  `success`, and the build got as far as transforming modules and reaching the
  broken file — so esbuild resolved and ran with scripts ignored.

## Production pass

1. **Failure paths** — the point of the change: `npm run build` failing now fails
   the job. `bash -e` per step plus the runner's exit-code check means the failure
   propagates; nothing swallows it.
2. **Untrusted input at the boundary** — this is the item the change addresses.
   A pull request from a fork proposes `package-lock.json`, and until now `npm ci`
   would run that lockfile's install hooks on the runner. `--ignore-scripts`
   closes it. Note the residual: build-time code (`vite.config.js`, plugins) still
   executes, so this is a reduction in blast radius, not an isolation boundary.
3. **Secrets** — n/a and confirmed: the workflow declares `permissions: contents:
   read` and passes no secrets; the added step interpolates nothing.
4-7. **Resources / timeouts / scale / observability** — n/a, two declarative
   workflow lines. The build takes ~5s locally and 2s on the runner; the job
   inherits the default 6h timeout, unchanged.
8. **Reversible** — one-line revert of `ci.yml`. No migration, no state.
9. **Public surface** — the check name contributors and ruleset 21038975 depend on
   is the job id `test`, deliberately unchanged. What changed is what that check
   means: it now also asserts the build compiles, so a pull request that was green
   before this commit and breaks the build will be red after it. That is the
   intent, but it is a stricter gate on existing open pull requests.
