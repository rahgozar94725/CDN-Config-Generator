## Instrument

`R9-instrument.html`, committed beside this record so the measurement is
repeatable. Served over `http://127.0.0.1:8765` by `python -m http.server`
because Playwright blocks the `file:` protocol.

- **Direction:** `<html lang="fa" dir="rtl">` — the same thing the app does at
  `src/i18n/index.js:33`, which sets `dir` on `documentElement` for `fa`.
- **Font stack:** Tailwind's default sans (`ui-sans-serif, system-ui,
  -apple-system, "Segoe UI", Roboto, "Helvetica Neue", Arial, "Noto Sans",
  sans-serif`). The app declares no custom `font-family` — `src/style.css` is
  three `@tailwind` directives and nothing else — so this is what it renders in.
- **Browser:** Chromium via Playwright, on Windows 10.
- **Method — numbers, not a look.** For each string, a `Range` is placed over
  every single character and `getBoundingClientRect()` read. Characters are then
  sorted by `(top, left)`. The resulting sequence is the **visual** order,
  left-to-right, measured rather than judged. Zero-width characters (the ZWNJs
  in the live Persian) are dropped, since they have no position to report.
- **Corroboration:** `R9-measured.png`, a full-page screenshot of the same page
  in the same run. It agrees with the numbers in every case.

**Reading the results below.** Persian is read right-to-left, so a correctly
rendered Persian word appears *reversed* in a left-to-right dump. `زا` in the
visual column is `از` read the way a Persian reader reads it. What matters is
not that the letters look reversed — they always will — but **where the trailing
neutral characters land relative to the Latin run, and whether their own order
survives**.

## The three measurements

### 1. `از VLESS.` — a single trailing neutral at end of string

- **gate verdict:** clean — `run="VLESS" trailing="." len=1`, below
  `MIRRORS_VISIBLY = 2`
- **observed visual order:** `.VLESS زا`
- **what that means:** rightmost is `از`, then `VLESS`, then `.` at the far left.
  An RTL reader scanning right-to-left gets `از` → `VLESS` → `.` — the period is
  the last thing read, which is where a sentence-final period belongs in RTL
  text. It is not stranded and it is not reordered.
- **verdict: renders correctly.** The browser agrees with the gate.
- **date:** 2026-08-20

### 2. `متن VLESS.مهم است` — a single neutral with no following space

- **gate verdict:** clean — `run="VLESS" trailing="." len=1` (the Persian `م`
  ends the neutral stretch immediately)
- **observed visual order:** `تسا مهم.VLESS نتم`
- **what that means:** reading right-to-left — `متن` → `VLESS` → `.` → `مهم` →
  `است`. The period sits between the Latin token and the Persian word that
  follows it, exactly where it is logically.
- **verdict: renders correctly.** The browser agrees with the gate.
- **date:** 2026-08-20

### 3. `rows.transportError` — the live value, with its em dash

Value read from `src/i18n/locales/fa.json`, not retyped:

```
این ترنسپورت از CDN رد نمی‌شود. فقط این‌ها رد می‌شوند: ws xhttp grpc httpupgrade — ترنسپورت را روی سرور عوض کنید یا این ردیف را حذف کنید.
```

- **gate verdict:** clean — two runs, `run="CDN" trailing=" " len=1` and
  `run="ws xhttp grpc httpupgrade" trailing=" " len=1`. The em dash is **not** in
  `TOKEN_NEUTRAL`, so it ends the run rather than trailing it.
- **observed:** wraps to 2 lines. Line 1 visual order ends
  `… :دنوشیم در اهنیا طقف  ws xhttp grpc httpupgrade —`, i.e. reading
  right-to-left: `… فقط این‌ها رد می‌شوند:` → `ws xhttp grpc httpupgrade` → `—`.
  Line 2 continues `ترنسپورت را روی سرور عوض کنید یا این ردیف را حذف کنید.`
- **what that means:** the em dash lands immediately after the Latin run in
  reading order and does not cross to the far side of it.
- **verdict: renders correctly.** The browser agrees with the gate.
- **date:** 2026-08-20

## What this decides

### Is `MIRRORS_VISIBLY = 2` the right threshold?

**The idea is right; the count it is applied to is wrong.** Measured, in three
parts:

1. **The "one is invisible" half is confirmed.** Both strings the plan named
   carry exactly one trailing neutral and both render correctly. Nothing here
   argues for lowering the threshold to 1.

2. **Counting whitespace produces false positives.** `یا رمزنگاری VLESS. هیچ`
   and `یا رمزنگاری VLESS. ` are both scored BROKEN on `trailing=". "` — one
   period plus one space — and both **render correctly**. The gate's own comment
   at `bidi.test.js:70-76` states the opposite outcome as its justification:
   *"a sentence period plus its space lands on the far side of the Latin token
   it was meant to follow."* Measured in Chromium, it does not. The period lands
   immediately after the token in reading order.

3. **Counting identical characters does too.** `متن VLESS.. ادامه` is scored
   BROKEN on `".. "` and renders correctly — reversing two identical characters
   is as invisible as reversing one, which is the gate's own stated reasoning
   applied one step further than the code applies it.

**The rule every measurement fits:** a trailing neutral run mirrors visibly when,
after removing whitespace, **two or more characters remain and they are not all
the same character**. Check: `://` → `://`, three distinct → visible (matches);
`:/` → two distinct → visible (matches); `. ` → `.`, one → invisible (matches);
`.. ` → `..`, identical → invisible (matches); `.` → one → invisible (matches);
`" "` → nothing → invisible (matches). Nine strings, no exceptions.

This is a finding, not a change. `src/meta/bidi.test.js` is outside this unit's
`Files`, and narrowing the gate is not what R10 does either — R10 writes the doc.

### Is `TOKEN_NEUTRAL` right to exclude the em dash?

**Yes, measured.** Two strings carry an em dash after a Latin run — the live
`rows.transportError` and the reduced probe `فقط ws grpc — ترنسپورت` — and both
render with the dash in the correct reading position. Excluding `—` from
`TOKEN_NEUTRAL` costs nothing observable here.

The plan flagged that `—` is Unicode bidi class ON, like `.` and `/`, and
wondered whether that made the exclusion wrong. The class is the same; the
outcome is not, because in both strings the dash is followed by a space and then
strong RTL text, so it resolves to the paragraph direction and lands where a
Persian reader expects it. Bidi class alone does not predict the rendering — that
is the whole reason this unit measured rather than reasoned.

## Does the browser agree with the gate?

On the three strings the plan named, **yes** — all three score clean and all
three render correctly. On the wider set, the gate is **sound but not tight**: it
never called a broken string clean, and it called three correct strings broken.
Its errors are in the safe direction, and they are the direction that annoys
authors rather than the direction that ships a garbled screen.

## Notes for the next unit

**R10 amends `docs/agents/persian-style.md` to state a threshold R9 measured.**
What it may now assert, and what it may not:

- **May assert, measured:** a single trailing neutral does not mirror visibly —
  both `از VLESS.` and `متن VLESS.مهم است` render correctly. Rule 2's absolute
  ban ("End-of-string does not save it") is stricter than what was observed, and
  R10 was already told to amend it to the measured threshold.
- **May assert, measured:** `://` and `:/` after a Latin run **do** mirror
  visibly, in both mid-sentence and end-of-string position. The doc's verdict on
  `پشتیبانی VLESS://` is confirmed rather than merely asserted.
- **May assert, measured:** the em dash does not mirror, so the doc can say the
  gate's exclusion of `—` is measured and not merely convenient.
- **Must not assert:** that the gate fails exactly the strings that render
  wrongly. It does not. `VLESS. ` renders correctly and the gate fails it. If
  R10 writes a threshold sentence, the honest one is about **non-space,
  non-identical** trailing neutrals, and it should say plainly that the gate
  currently counts whitespace and so is stricter than the rendering requires.
- **Carried over from R4, still true and now measurable:** the gate's real rule
  is "a run containing at least one `[A-Za-z]` must not end on two or more
  neutral characters". R9 adds: and that rule over-fires whenever the second
  neutral is a space or a repeat.

**A new finding neither R9 nor R10 is scoped to fix.** The false-positive class
above is a defect in `src/meta/bidi.test.js`, not in the doc. Making the gate
match the measurement means changing `brokenRuns` to strip whitespace and ignore
runs of identical characters — one line, and a `Files` entry no unit currently
has. It belongs in `## Deferred` or in a new unit, and the decision is the
repository owner's. Note the direction of the error: the gate is over-strict, so
nothing broken is shipping because of it. It costs author friction, not
correctness — which is an argument for scheduling it, not for rushing it.
