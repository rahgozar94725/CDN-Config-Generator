## What changed

The traceability gate now rejects four inputs it used to accept in silence: a
`V<n>:` tag on a test the runner never executes, an `UNTESTED_BY_DESIGN` entry
with no §V row (or any entry beyond `V9`), a §T `cites` column naming a §V id
that has no row, and a directory or non-`.md` file in `docs/adr/` standing in
for an ADR. The gate's rules are unchanged; only its enforcement got tighter.

## Files

- `src/meta/traceability.test.js` — skip/todo/fails filter in `testTags`, exemption-list assertion, `unresolvedCitations` helper reused for §T, `adrFiles` filtered to `NNNN-*.md` and added to the canary (with `tasks`)

Every red was produced by making the repository temporarily contain the bad

the gate reads the real repo, so that is the only way to feed it. Hole 1 and

## Production pass

- **1/2 (failure modes, error handling):** `readdirSync(docs/adr)` still throws
  at module load if the directory is gone — an ENOENT naming the path, at the
  moment the repo is already broken, so a catch would only convert a loud
  failure into a quieter one. Left as is. `rowId(row)` can return null on a
  malformed row in theory, but `sectionRows` filters lines on the same
  `^|\s*X\d+\s*|` pattern `rowId` matches, so the null branch is unreachable.
- **6 (scale):** the `adrFiles` filter is one regex per directory entry over a
  7-file directory; `unresolvedCitations` is O(rows × cited ids). Nothing here
  grows with repo size in a way that matters.
- **3, 4, 5, 7 (config, secrets, concurrency, logging):** n/a — test-time code
  reading two paths under the repo root, no I/O beyond reads, no state.

## Notes for the next unit

R6 edits this same file. What it will find:
- `testTags` is no longer a one-liner: it is a `matchAll` → `.filter` (line-prefix
  check for `.skip(`/`.todo(`/`.fails(`) → `.flatMap`. It uses `m.index`, so any
  refactor must keep the match objects, not just their groups.
- New module-level bindings: `tasks` (§T rows) and `unresolvedCitations(rows)`,
  the helper the §B and §T citation tests share. `adrFiles` is now filtered to
  `/^\d{4}-.+\.md$/`.
- The canary `found the tables it audits` gained two assertions (`tasks.length`,
  `adrFiles.length`). Anything R6 adds that reads a new input should extend that
  same canary rather than introduce a second style.
- Two decisions worth carrying: `V999` is taken as the sentinel by the existing
  untested-id fixture, so a new fixture needing a bogus id should pick another
  (V998 is free); and any literal test-name string added to this file must be
  split (`"'V" + "6: x'"`, mirroring the existing `'see ADR-' + '0099'`) or it
  will be scanned as a real tag by the gate auditing itself.
