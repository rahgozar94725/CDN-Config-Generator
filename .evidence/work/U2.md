## What changed

`npm run test` — and therefore the CI job U1 added — now goes red when SPEC.md
drifts from the code: a `§V` invariant with no test named after it, a `V<n>:`
test tag whose row was deleted, a `§B` defect citing a `V<n>` or ADR that does
not exist, or an `ADR-000N` anywhere in `src/` or SPEC.md with no file in
`docs/adr/`. Seven previously unanchored invariants are now tagged onto the
tests that already asserted them; V9 is the single named exemption.

## Files

- `src/meta/traceability.test.js` — new. The whole gate: reads SPEC.md,
  `src/**` and `docs/adr/` as text, no imports of the modules it audits.
- `src/utils/rows.test.js` — `V12:`, `V14:`, `V16:`, `V18:` prefixed onto four
  existing test names; assertions untouched.
- `src/utils/generation.test.js` — `V17:` prefixed onto two test names.
- `src/utils/multiplier.test.js` — one test retagged `V7, V15:` (comma run).
- `src/utils/parser.test.js` — `V11:` prefixed onto two test names. Was outside
  the plan's declared `Files` list at the time; the plan was amended on
  2026-08-18 to declare `src/utils/**/*.test.js` as a derived set with exactly

## Production pass

1. **Every failure path goes somewhere** — the gate's only fallible calls are
   `readFileSync`/`readdirSync` at module scope. A missing SPEC.md or
   `docs/adr/` throws at collection and vitest reports the file as failed —
   loud, not swallowed. No catch anywhere in the file.
2. **Untrusted input validated at the boundary** — the boundary is SPEC.md's own
   shape, and a renamed heading or reformatted table would silently empty every
   list and make the gate vacuously green. The first test
   (`found the tables it audits`) asserts `invariants`, `defects` and `tagged`
   are all non-empty for exactly that reason.
3. **Nothing secret in logs/errors/repo** — n/a. The gate reads repo-tracked
   markdown and source; failure messages interpolate ids and repo-relative paths
   only.
4. **Resources released on every path** — n/a. Synchronous `fs` reads, no
   handles, sockets, timers or watchers held.
5. **Timeouts / retry safety** — n/a. Nothing remote, nothing retried, nothing
   written.
6. **Behaves at real size** — walks `src/` (29 files today, all text: js, vue,
   json, css) and `docs/adr/` (7 files), reading each once. Linear in file
   count; 20ms of the 3.0s suite. Would stay fine at 10x the repo.
7. **Observability when it misbehaves** — every assertion carries a custom
   message string naming *which* ids failed and, for ADR citations, which file
   cited them, so a CI log line is a starting point rather than a shrug.
8. **Can be undone** — deleting `src/meta/traceability.test.js` removes the gate
   entirely; the test-name tags are inert prefixes. Not a one-way door.
9. **Public surface is honest** — no runtime code changed. `src/meta/` is a new
   directory picked up by vitest's default glob with no config change; nothing
   imports it. Six test *names* changed, which is visible in CI output — noted
   in the commit message.

## Notes for the next unit

- **Scope deviation to carry forward:** the plan's `Files` list for U2 omitted
  `src/utils/parser.test.js`, because it predicted the red set as
  `V9, V12, V14, V15, V16, V17`. The measured red set was
  `V11, V12, V14, V15, V16, V17, V18` (V9 exempt). V11 is about parser
  derivation and its only honest anchors are the two tests in
  `parser.test.js:122` and `:140`, so that file was tagged rather than
  mis-anchoring V11 onto a rows or generation test. Same mechanical edit as the
  declared ones (name prefix only). Expect the same class of drift in U3/U4:
  the plan's predicted violation sets are estimates, not measurements — take the
  gate's first red run as the truth and record the delta.
- **The tagging convention U3/U4 inherit:** a test name may open with a
  comma-separated run, `it('V7, V15: …')`, and every id in the run counts. Use
  it instead of duplicating a test to carry a second id.
- **`src/meta/` now exists** and vitest picks it up with no config change —
  `vite.config.js` still sets no `test.include`. U3's `src/meta/locales.test.js`
  and U4's `src/meta/bidi.test.js` need no wiring, just the file.
- **Gate style precedent worth copying:** the `found the tables it audits` test.
  A gate that parses files can go vacuously green when the thing it parses is
  renamed. U3 (locale key parity) and U4 (bidi rules over `fa.json`) have the
  same exposure — assert the parsed input is non-empty before asserting anything
  about it.
- **A gate's own fixtures must not be scanned by the gate.** `traceability.test.js`
  splits its negative fixture as `'ADR-' + '0099'` so the ADR resolver does not
  read its own test data as a real citation, and keeps synthetic ids (`V999`,
  `V99`) out of quote-then-colon position. U3/U4 will hit this the moment they
  scan `src/**` for anything.
- **`UNTESTED_BY_DESIGN` in `src/meta/traceability.test.js` is the repo's only
  exemption list.** If U3 or U4 needs one, mirror the shape — a named constant
  with the reason inline, greppable, one line to delete — rather than a baseline
  file. The plan allows exactly one exemption per gate and V9 spent U2's.
