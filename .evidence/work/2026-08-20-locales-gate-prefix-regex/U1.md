## What changed

`dynamicPrefixes` now records a prefix only when the `t` opening the call is not
preceded by an identifier character or a `$`, so ordinary calls whose name merely
ends in `t` (`format(`, `expect(`, `parseInt(`, `split(`) no longer donate phantom
prefixes, while `t(`, `$t(`, `i18n.t(` and `this.$t(` still do. Four fixture tests
pin that boundary, and the helper's doc comment now carries the reasoning and the
scan's blind spots. The live tripwire is unchanged and still reads `['theme.']`.

## Files

- `src/meta/locales.test.js` — lookbehind `(?<![\w$])` on both `dynamicPrefixes`
  patterns, an extended doc comment above the helper, and four new `it(...)`

## Production pass

Ran because the unit is a mechanism that reports on something else — a CI gate over
the locale files. Changed nothing about the code; recorded below.

- adversarial (the one that matters here): a narrowed scan could hide a real
  composed call and make the tripwire falsely green. Traced every consumer of
  `prefixes`. `unknownKeys` uses it as an *exclusion* list, so dropping entries can
  only create a false red, never a false green. `orphans` does not use it at all —
  it composes from `themeNames`. That leaves the tripwire, where a missed genuine
  call would be a real false green; but the only strings the lookbehind now rejects
  are `t(` preceded by `\w` or `$`, which in JavaScript cannot be a call to a
  binding named `t` or `$t`. Member and bare calls both still match, pinned by the
  new member-call fixture. No reachable false-green case found.
- adversarial, second: the `[\w.]*` capture. A fully dynamic `t('' + k)` yields
  `''`, which reaches the tripwire and turns it red rather than passing in silence
  — pinned by its own fixture, and the reasoning is now in the doc comment.
- correctness 1 (empty-collection / boundary): the fixed patterns are still global
  `matchAll` over possibly-empty text; `[...matchAll]` on no match yields `[]` and
  the helper returns `[]`. Confirmed by the ordinary-call fixture's green.
- correctness 7 (silent meaning change): the change is a narrowing of a matcher,
  which is exactly a silent meaning change — which is why the live tripwire
  assertion was left untouched as the control. It still reads `['theme.']`.
- tests 1/6: every new behaviour has a fixture that fails if it regresses, and none
  of them mirror the regex — each states a call shape and the prefix it should or
  should not yield, so a wrong regex disagrees with them.
- correctness 2-6, interruption, observability, security, real size, reversibility
  — n/a. Pure function over a string, no I/O added, no state, no untrusted input
  beyond files already read, no signature or default changed, and the change is a
  one-line regex edit inside a test file, trivially reversible.
