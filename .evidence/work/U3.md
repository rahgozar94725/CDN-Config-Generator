## What changed

A locale key that exists in one of the four files and not the others, or that
exists in all four and is rendered by nothing under `src/`, now fails the test
suite by name. The four keys that were already orphaned — `config.ports`,
`output.title`, `common.clear`, `common.ready` — are deleted from all four
files, so the gate ships green rather than grandfathering its own violations.

## Files

- `src/meta/locales.test.js` — new. The gate: key-set parity across the four
  locale files, an orphan check over `src/` call sites, and a pinned set of
  runtime-composed key prefixes.
- `src/i18n/locales/{en,fa,ru,zh}.json` — the four orphaned keys deleted from
  each. 57 keys to 53, all four still in parity.

## Production pass

1. **Every failure path goes somewhere** — the fallible calls are `readdirSync`,
   `readFileSync` and `JSON.parse` at module scope. A renamed locale directory
   or a malformed locale file throws at collection and vitest reports the file
   as failed. No catch anywhere, so nothing is swallowed.
2. **Untrusted input validated at the boundary** — the boundary is the shape of
   the locale directory and of the source tree, and the failure mode is silent
   emptiness rather than a crash: a moved directory would leave every list empty
   and the gate would pass by checking nothing. The `found the files it audits`
   test asserts non-empty locale files, call sites and quoted strings, mirroring
   `traceability.test.js:71`.
3. **Nothing secret reaches a log** — n/a. The gate reads locale strings and
   source text and prints key names; no credential is in scope.
4. **Resources released on every path** — n/a. `readFileSync` holds no handle.
5. **Timeouts / safe retries** — n/a. No network, no writes, no retries.
6. **Behaves at real size** — reads ~30 files once at module scope and does
   `keys x prefixes` comparisons with one prefix and 53 keys. The `quoted` array
   is a list rather than a `Set`, so the orphan scan is O(keys x quoted); at 53
   and ~900 that is nothing, and a `Set` is the one-line change if the repo ever
   grows an order of magnitude.
7. **Something says so when it misbehaves** — every assertion carries a message
   naming the offending key, and the parity message names the files too. That is
   the whole diagnostic; no further logging is useful for a string check.
8. **It can be undone** — the deletions are four lines per file and revert with
   the commit. Nothing rendered these keys, so there is no runtime behaviour to
   restore alongside them.
9. **The public surface is honest** — four locale keys are removed. Grepped the
   whole repository outside `.evidence/`: the only remaining mention is
   `docs/ideation/2026-08-14-open-ideation.html:406`, which is a dated record of
   the problem and correctly stays as written. It names three of the four, which
   is a small argument for the gate: the hand-audit missed one.

## Notes for the next unit

- The gate's orphan rule is deliberately loose: a key counts as live if it
  appears quoted *anywhere* in a non-test source file, comments included. A
  call-site-only scan reported all eight `rows.*Error` keys as dead, because
  `ConfigRows.vue:116` reaches them through a lookup table. The loose rule can
  keep a key alive by a stale mention; the tight one raised eight false alarms
  on day one. The trade is stated in the file above `orphans`.
- `EXPECTED_DYNAMIC_PREFIXES` is pinned to `['theme.']` and asserted by equality,
  not by a size bound. A new `t(prefix + x)` call site fails the gate until
  someone adds the prefix — deliberately, because each such prefix is a region
  the orphan check cannot see into.
- U4 edits `fa.json`. It should expect 53 keys, not the plan's 57.
- U4 can mirror this file's shape directly: pure helpers over text read from
  disk, one `found the files it audits` guard, real-data assertions, then
  synthetic negative cases for the error scenarios. No harness, no mounting.
- The measured orphan set matched the plan's prediction exactly, so U3 used no
  part of its amended derived scope. That amendment cost nothing and is still
  the right shape — U4's prediction is a single key and is the one more likely
  to be wrong.
