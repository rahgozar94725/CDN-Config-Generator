## Production pass

1. **Failure paths** — the gate's own inputs are `readFileSync` and `JSON.parse`
   on one file. Both throw, and a throw fails the suite, which is the intended
   behaviour: a `fa.json` that cannot be read must not be reported clean. The
   `found the file it audits` test covers the quieter failure — a moved or
   renamed file leaving the gate with nothing to check and passing by vacuity.
2. **Boundary validation** — n/a. Nothing crosses a trust boundary; the only
   input is a repository file.
3. **Secrets** — n/a. No credentials, no network, no logging.
4. **Resource lifetime** — n/a. One synchronous read, no handle held.
5. **Timeouts / retries** — n/a. Nothing remote.
6. **Real size** — the scan is linear in the total length of `fa.json` and runs
   in 24ms over 53 keys. At ten times the file it is still a single pass.
7. **Observability** — the failure messages carry the locale key and the exact
   offending substring, which is the whole starting point a reader needs.
8. **Reversible** — deleting `src/meta/bidi.test.js` removes the gate entirely;
   the `fa.json` reshape is a one-line revert.
9. **Public surface** — no runtime code changed. `rows.flowError` renders a
   longer Persian sentence in the UI; the English, Russian and Chinese values
   are untouched, as the unit's `Files` requires.

## Notes for the next unit

- The threshold this gate turns on is **a trailing neutral run of two or more
  characters**, not "any trailing punctuation". That is what reconciles the
  doc's own verdicts: `://` reverses to `//:` and a period plus its space lands
  on the far side of the token, but a lone `/` reverses to itself, which is why
  `لیست IP/دامین CDN` is measured ok. Loosening the threshold to one character
  would fail `input.cdnList.label` and several `rows.*` strings that render fine.
- `TOKEN_NEUTRAL` is a string, not a regex character class, because an
  unescaped `/` inside a class is legal JS that Vite's import lexer ends the
  literal on — it reports `invalid JS syntax` pointing at the last line of the
  file, which is a long way from the actual character. Worth knowing before
  writing the fourth gate.
- Reverting a probe with `git checkout -- <path>` also discards uncommitted
  real work in that file. It cost one re-apply here. Commit the change before
  injecting a probe into the same file, or edit a copy.
