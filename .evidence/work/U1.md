## What changed

A pull request against this repository now runs the vitest suite and reports a
check. Before this, CI ran only `npm ci` + `npm run build`, and only after a
merge landed on `master` — a red suite could reach production unnoticed.
`deploy.yml` is untouched, so the Pages deploy keeps its own concurrency group
and write permissions.

## Files

- `.github/workflows/ci.yml` — new; `pull_request` + `push` on `master`, runs `npm ci` then `npm run test`.

## Production pass

1. **Failure paths** — the only failure modes are a non-zero exit from `npm ci` or `npm run test`; both propagate to the step and fail the check. No `continue-on-error`, no `|| true`. Observed exit 1 above.
2. **Untrusted input at the boundary** — the trigger is `pull_request`, not `pull_request_target`. A fork's pull request therefore runs against the merge ref with a read-only, fork-scoped token and cannot read repository secrets. This is the security-relevant choice in the file.
3. **Secrets** — `permissions: contents: read` only. No `secrets.*` is referenced and nothing is echoed. The job publishes nothing.
4. **Resource release** — n/a; an ephemeral GitHub-hosted runner is torn down by the platform.
5. **Timeouts / retries** — no `timeout-minutes` is set, so GitHub's default 360-minute job timeout applies. The suite runs in ~4.5s locally, so the exposure is a hung vitest burning runner minutes. Left at the default rather than added, because the Approach did not call for it; flagged here as a one-line change if it ever bites.
6. **Real size** — 973 tests / 6 files / ~4.5s. `npm ci` with the npm cache is the dominant cost. Nothing here grows with data.
7. **Observability** — vitest names the failing file, test and line in the check log (see the red above). That is the whole ask for this unit.
8. **Reversible** — deleting the file reverses it completely. Important caveat: this workflow only *blocks* a merge if branch protection requires the check. Whether protection is on for `master` is an open item in the plan's `## Deferred` and could not be read this session.
9. **Public surface** — a new check named `test` now appears on every pull request and on pushes to `master`. Contributors will see it; if branch protection is later configured, it is the check to require. Named in the commit message.
