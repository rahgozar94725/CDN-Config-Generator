No subject was specified, so six ideation frames each picked their own from the repository. They converged hard on one thing and diverged usefully on the rest. An independent verifier — which never saw the ideas being written — then tried to refute every basis by reading and running the code. Grounding Context

Codebase Context

A client-only Vue 3 SPA that multiplies proxy configs across CDN edge nodes: paste origin configs (vless/vmess/trojan/ss) plus a CDN host list, and it swaps the connect address per CDN host while preserving the CDN routing identity in host/sni. Audience is the Iranian Xray proxy community. Four locales (en/fa-RTL/ru/zh), deployed to GitHub Pages, no backend, and only two runtime dependencies — vue and vue-i18n.

The domain lives entirely in src/utils/ as pure JS with zero Vue imports: parser.js (per-scheme parsing plus routing-subdomain derivation), rows.js (allowlists, the compatibility gate, subdomain validation), multiplier.js (the CDN × port × TLS × ALPN × fingerprint cross-product and the link builders), dedup.js (normalized link identity and per-label numbering), and generation.js (the orchestrating pipeline). App.vue is the sole state owner with 14 refs plus a reactive(new Map()) override store.

What the repository already knows about itself

  • A real traceability chain: 18 invariants (V1–V18) in SPEC.md §V ↔ a 10-entry defect log (B1–B10) ↔ six ADRs ↔ test names literally prefixed V1:, V4:. Four invariants have already been rewritten by ADRs, so the set is living, not historical.
  • Twenty-one design directions are explicitly closed by ADRs — punycode, PSL validation, SIP002 plugin dialect, exact-string dedup identity, global remark counters, lenient IP fallback, and more. Ideation was constrained to stay outside all of them.
  • The governing principle, stated in ADR 0001 and applied everywhere: silently emitting broken links is worse than blocking.
  • Comments are load-bearing house style — nearly every non-obvious function carries a paragraph citing the ADR and the defect that produced it.
  • Every UI string costs four locales plus four READMEs. Four separate ADRs each paused to restate that cost.
  • 140 tests pass locally. CI runs npm ci and npm run build and nothing else.

External context

  • The VLESS/VMess share-link "standard" is still an unratified 2020 GitHub issue (XTLS/Xray-core #91); pbk/sid/spx/fp have no normative source at all. SIP002 is the one genuinely normative grammar in the set.
  • 2026 interop expectation is three dialects — URI list, Clash-Mihomo YAML, sing-box JSON — and Mihomo's shape for the same node differs structurally (servername not sni, ws-opts.headers.Host not host=).
  • Cloudflare error 1013 is literally "HTTP hostname and TLS SNI hostname mismatch" — the exact failure a wrong host=/sni= pair produces, and research names this the #1 user failure class in the space.
  • Clients drift: NekoBox rejects VMess configs v2rayNG accepts; v2rayNG silently discards SIP002 plugin params; Xray-native JSON is unsupported across several popular clients.
  • Config diffing appears unoccupied — no tool found shows "your config versus the last one you generated" (a negative result from targeted, not exhaustive, searching).

1

The vmess round trip is broken — and the test suite bakes it in

Confidence 95% Complexity Medium
Description

The app cannot read its own vmess:// output. buildVmess emits btoa(encodeURIComponent(json)); decodeBase64 expects base64 of UTF-8 bytes, so it hands back the percent-encoded string unchanged and JSON.parse fails. parseVmess swallows that in its own try/catch and returns null — no throw, no message, no symptom anywhere in the app. The fix is the missing unescape in the canonical btoa(unescape(encodeURIComponent(json))) idiom, but the idea is the gate around it: assert parse(build(x)) ≡ x as a property, so "output must be re-readable as input" becomes an invariant instead of a discovery.

Basis

direct: Confirmed by execution against head cd3bc3f. A link built through the real generateConfigs and fed to the real parseVmess returns null — identically for an ASCII remark and for a Persian-plus-emoji remark. decodeBase64 percent-escapes every byte and then decodeURIComponents, which round-trips the already-percent-encoded payload back to itself. dedupeAndNumber survives only because of the fallback at dedup.js:60-62 — dedup patched around the double-encoding once; the parser never got the same patch. No test covers this round trip, and multiplier.test.js:178 and :205 assert via JSON.parse(decodeURIComponent(atob(...))), encoding the bug as the expected shape.

Rationale

Eighteen invariants, ten logged defects, six ADRs and 140 green tests did not catch that a quarter of the tool's output is non-standard — because nothing in the system ever closes the loop. The repository's own governing principle is that silently emitting broken links is worse than blocking, and this is that failure committed by the tool itself. The property is what generalizes: it catches the next parameter the ecosystem invents, and — per idea 5 — every future output dialect inherits it for free.

Downsides

Not a typo fix. Two existing assertions must change, and dedup.js's tolerant fallback has to stay forever so that links already distributed under the old encoding remain dedupable — that is a compatibility decision with an ADR attached. Adding fast-check for the property layer means a devDependency, which runs against the ADR 0003 precedent (that precedent was about runtime data files and libraries, so the argument is winnable, but it must be made rather than assumed).

2

Seed the nonce, then diffing and probe plans become possible

Confidence 80% Complexity Medium
Description

Three ideas that arrived from three different frames turn out to be one chain. genRandomSni calls Math.random() unseeded, so the same paste with the same settings never reproduces — which quietly makes the other two unbuildable. Add an optional displayed, copyable seed, and two features open up: a cross-run diff (the real loop is rotation — same forty hosts, new origin config, every few days — so what the user needs at run N is added / unchanged / removed, not another opaque 5,000-line blob), and a probe plan (instead of hundreds of links tried by hand on a phone over a censored connection, emit eight to fifteen ordered links, each labelled with what its failure would prove).

Basis

direct: genRandomSni calls Math.random() twice unseeded (multiplier.js:135,139), verified. generateConfigs is a literal five-factor full factorial of nested loops (multiplier.js:29-50). linkIdentity (dedup.js:90-94) is already an exported, pure, order-insensitive, nonce-tolerant canonical identity with 24 tests — it was built for within-batch dedup and is exactly the key a cross-time diff needs. A seed does not participate in link identity, so ADR 0006 stays closed.

external: The reproducible-builds project solved the same shape with SOURCE_DATE_EPOCH — declared nondeterminism made reproducible rather than removed. Combinatorial testing (NIST's work behind PICT and ACTS) is the basis for the probe set: faults are overwhelmingly triggered by one- or two-factor interactions, so a pairwise covering array finds nearly all of them in a fraction of the runs. Research flags cross-run diffing as an unoccupied gap in this space.

Rationale

Every other feature on the list means competing with subconverter and sublink-worker on their own ground. This one lands where the research found nothing, and the hard part — a canonical identity surviving query reordering and a nonce SNI — is already built, tested and ADR-justified. The reframe is that the tool acquires a memory: it stops being a one-shot generator and starts answering "what changed" and "which twelve should I try first."

Downsides

Ordering is load-bearing — build the seed first or the other two are not buildable as specified. Storing the previous run raises the same privacy question idea 6 has to settle, since a stored run is a stored set of working links. The probe plan changes what the product claims to deliver (a plan, not a list), which is a positioning call as much as a feature.

3

Governance CI: one job, four gates

Confidence 90% Complexity Low
Description

All six frames landed on this independently. CI runs npm ci and npm run build, so a red suite ships to production today. But the merely-obvious half (add npm test) is worth much less than the rest: parse SPEC.md §V and fail when any invariant has no test carrying its ID; fail when a B-number has no regression test or an ADR reference no longer resolves; assert the four locale files have identical key sets and no unused keys; and turn the two mechanically decidable Persian rules — Latin runs must be contiguous, and a Latin run must end on a Latin letter, with U+200E and U+2068/9 banned — into pure string assertions.

Basis

direct: .github/workflows/deploy.yml:29-30 is exactly npm ci then npm run build; a test script exists in package.json and CI never calls it. Only five test files exist, all under src/utils/ — no locale, parity or bidi test anywhere. Three keys (config.ports, common.clear, common.ready) have zero references in src/, which is what unenforced parity looks like after a few passes. And the chain has already rotted at its newest link: ADR 0002 still claims the ru/zh READMEs carry a stale host/sni claim that commit d018f10 fixed. docs/agents/persian-style.md states its rules as measurements and then asks the author to paste a devtools snippet and read reversed output by eye — a rule that says "verify, don't eyeball" is asking to be a test.

Rationale

The repository's distinctive asset is not its tests — it is the invariant / defect / ADR chain that made B10 ("defects of B9's own fix") legible instead of mysterious. A chain that can silently rot is decorative, and this one has already started. Mechanizing it also converts the four-locale tax — a cost four consecutive ADRs each paused to warn about — from a discipline problem into a red test, which is the difference between a rule that survives contributor number two and one that does not.

Downsides

Meta-tests that parse prose are brittle: a reformatted SPEC table breaks the build for a non-defect, and the bidi checker will need an escape hatch for legitimately unusual strings. The verifier also found that the neighbouring idea — asserting each rejected ADR option — is weaker than it looks, since two of them are already covered by existing tests and most closed decisions (the Persian register, "PRs are not a request surface") are not mechanically assertable at all.

4

Four allowed transports, one link shape

Confidence 85% Complexity Medium
Description

The allowlist admits ws, xhttp, httpupgrade and grpc, but the builder branches only on TLS-versus-none — never on transport. Every emitted link gets host set to the routing subdomain, and every TLS link additionally gets insecure=0 and allowInsecure=0. For gRPC the share-link grammar is serviceName/mode, and host= is not part of it; XTLS issue #91 explicitly excludes allowInsecure. Audit what is actually emitted per transport against the real client grammars, and then either narrow the allowlist or shape the builder — settled the way ADR 0004 settled flow, on source evidence rather than reasoning.

Basis

direct: All three code facts verified at head. multiplier.js:81 is p.host = config.routingSubdomain with no transport branch; multiplier.js:85-86 writes insecure=0 and allowInsecure=0 inside the single if (security === 'tls'); and grpc appears nowhere in src/ except the allowlist, four locale strings, and two row tests — there is no gRPC branch in any builder and no test asserting gRPC output shape. The verifier also surfaced an asymmetry nobody had noticed: parser.js:96-106 whitelists nine vmess keys, so serviceName, mode and seed are destroyed at parse time for vmess while vless, trojan and ss keep every query param. gRPC is therefore broken differently per scheme.

external: XTLS/Xray-core issue #91 — the closest thing to a share-link standard — lists serviceName and mode as the gRPC parameters and explicitly excludes allowInsecure.

Rationale

ADR 0004's entire argument for allowlists was that an unrecognized value must never be silently rewritten. The allowlist honours that on the input side while the builder rewrites the output side for three of the four admitted transports with no per-transport evidence. Thirty commits of correctness work have never touched this file's transport blindness, and all 140 tests are blind to it. If the gRPC reading holds, this is the highest-severity open defect in the repository.

Downsides

The spec question is genuinely unresolved and cannot be settled from inside the repository — it needs the same source-level check ADR 0004 used for flow, against an unratified issue thread and real client behaviour. Narrowing the allowlist would refuse configs that work today for some users; shaping the builder per transport adds branches to the file with the most delicate history. Either answer belongs in an ADR so nobody re-asks.

5

Emitter registry: split the cross-product from the dialect

Confidence 75% Complexity Medium
Description

buildLink is a switch over uniform leaf builders, wrapped in a cross-product loop that is entirely dialect-agnostic. Split them: the loop yields link specs, and a registry maps a target output format to an emitter. Dropping the idx parameter is required by the split and simultaneously deletes the dead three-digit counter that generation.js already documents as irrelevant. Afterwards, "also emit Clash-Mihomo YAML and sing-box JSON" becomes one emitter each instead of an edit across the cross-product, the dedup identity and the numbering — the three places that produced B9 and B10.

Basis

direct: buildLink is a switch (config.type) over uniform leaf builders. The suffix at multiplier.js:56-58 is provably dead: generation.js calls the multiplier one config at a time so the counter always restarts, dedup.js strips and rewrites the fragment anyway, and generation.js:91-92 already says so in a comment — two numbering implementations, one of which does nothing. Verified.

external: The 2026 interop expectation is three dialects, and Mihomo's outbound shape for the same node differs structurally — servername rather than sni, ws-opts.headers.Host rather than host=. hiddify/ray2sing exists specifically because URI-to-sing-box conversion is non-trivial.

Rationale

This is the largest capability gap against subconverter and sublink-worker, and the split converts it from a rewrite into an additive change. It also compounds with idea 1: once the round-trip property exists, every new emitter inherits it instead of needing its own test family. The dead-code removal makes the refactor worth doing even if no second dialect is ever shipped.

Downsides

Refactoring the file with the most delicate defect history, on a codebase whose own log records a fix that broke itself. Each new dialect also needs its own identity normalizer for dedup, which is not free. And sing-box is a moving target — fields deprecated in 1.11 were removed in 1.13 — so an emitter is a maintenance commitment, not a one-time addition; generators in this space pin the wrong shape constantly.

6

The distribution decision: one file, no trace

Confidence 70% Complexity Medium
Description

A tool built for users behind national filtering is distributed exclusively as a URL on one blockable host. Add a single self-contained HTML build — all JS, CSS and locales inlined — attached to a GitHub release by the same workflow that already deploys Pages, so the app can be forwarded over Telegram, kept on a USB stick, and opened from file:// with no network at all. Paired with it is the question the codebase has never asked out loud: which state is a secret. One frame proposed persisting and URL-sharing the non-secret half (host list, port and ALPN selections, fingerprint) while structurally excluding pasted configs; another argued that for this audience the forensic footprint is itself part of the threat model and the share hash should be rejected in an ADR. These are one decision with opposite answers and have to be settled together.

Basis

direct: The app has no backend and two runtime dependencies, so inlining is a build-config change rather than an architecture change. App.vue's 14 refs are the extraction target for anything needing persistence or URL state, and the override map is keyed on a fingerprint composed of type, UUID, address and port — credential-bearing, so the override half of any "share your setup" feature needs re-keying before it is safe. Verified. OutputPanel.vue:72 already swallows clipboard errors with a bare catch.

external: vite-plugin-singlefile is real and build-time only; six-two/qr.html is the established single-standalone-file precedent in this niche. The concrete landmine is documented: clipboard-read permission prompts fire in Chromium when a page is opened from file://, and copy-to-clipboard is this app's primary output affordance. On the other side, crontab.guru advertises client-side-only parsing as a feature — a privacy claim that carries unusual weight for this audience, and one every Worker-backed panel in the space structurally cannot make.

Rationale

Every design decision in the repository optimizes the correctness of the links while the availability of the generator itself rests on a single hostname. For this audience that ordering is inverted. The two halves also make each other coherent: a build that forbids runtime fetches is exactly the build that can honestly claim nothing leaves the browser, and today "we make zero network requests" is an accidental property rather than a stated one. Deciding them together produces one ADR; deciding them apart produces two features that contradict on the clipboard and persistence questions.

Downsides

An offline copy whose copy button silently fails is worse than no offline copy, so the file:// clipboard path has to be tested rather than assumed. The single-file build costs one devDependency, which runs against the ADR 0003 precedent. And the zero-trace answer forecloses the most attractive feature request this project will ever receive — which is an argument for writing the ADR now, not later.

7

Say which hop reads which field — from one control table

Confidence 65% Complexity High
Description

The most valuable thing this tool knows is the thing it never says out loud: the client connects to a CDN edge at the address, the edge routes on the name in host/sni, and getting that pair wrong is Cloudflare error 1013. Surface it — hover or expand a generated link and see each field labelled with which hop consumes it, including the deliberate absence of sni when there is no TLS handshake. Underneath it, lift the refusal policy out of an ordered if chain into a declarative table (condition → reason key → precedence → ADR citation) that is simultaneously the implementation, the test fixture, and the rendered explanation.

Basis

direct: multiplier.js:90-91 carries exactly this knowledge in a comment no user sees — "No TLS handshake, so there is no server name to indicate. Writing one added a parameter the origin config did not have and nothing reads." rows.js:44-46 carries a safety-critical ordering constraint in prose: an ss link in the plugin dialect states its transport inside plugin and so carries no type param at all, so checking the transport first would blame the wrong thing. Reason strings are already message keys rendered generically by the row UI, so the plumbing for typed, localized explanations exists and is currently wired only to failure. Verified.

external: Cloudflare error 1013 is literally "HTTP hostname and TLS SNI hostname mismatch", and research names host/SNI confusion the #1 failure class in this space. regex101's explanation pane and RegExr's hover-to-highlight are the proven interaction; the domain analogue is hovering sni= and seeing which hop it applies to.

Rationale

Every competitor generates; none teaches. The knowledge that makes this tool correct is currently invisible to its users and duplicated four ways for its maintainers — as code comments, SPEC rows, ADR prose, and four READMEs. One extraction collapses the duplication and converts documentation debt into the feature that answers the audience's most common mistake from the inside. A user who understands the two hops can debug a dead link themselves; a user who does not can only regenerate and hope. It is also the only survivor here that changes what the product is rather than what it checks.

Downsides

The highest string tax on the list — four locales plus four READMEs — and annotating Latin runs inside Persian RTL text is precisely the project's signature unsolved problem. The verifier also cut this idea down: a broader version bundling the CDN-port gate and per-client profiles onto the same table was rejected as four unbuilt surfaces assumed to share one schema, and one of those four rested on a wrong premise (the port chips are a fixed set already equal to Cloudflare's proxied list, so there is nothing there to gate; the genuinely ungated knob is ALPN, where h2 is selectable for a WebSocket config over an HTTP/1.1-only edge). Start with the table and the annotation, not with the whole ambition.
